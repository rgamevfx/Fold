Native orthographic camera and shared projection/depth — 8 October 2026
M5 implementation evidence; complete M3–M5 gates remain open.

Added fold.motion.camera v1 mode orthographic with typed, animatable vertical_size
in world meters (default 4; supported range 1e-6 through 1e6). It shares position,
look-at, up, clipping and exposure controls with perspective mode. Existing graph
catalog/inspector/transaction controls supply its artist surface; no toolbar or
alternate editing implementation was added. Fold UI skill applied. Physical normal/
narrow review of this specific camera remains unverified.

Native evaluated cameras and feature-neutral renderer cameras now carry an explicit
Perspective/Orthographic projection enum. Authoring retains perspective's existing
vertical_fov parameter; observation camera snapshots expose projection.kind plus
vertical_fov or vertical_size. No unused perspective FOV or compatibility alias is
stored on an orthographic camera. Camera binding hashes include kind and size using
a revised hash domain, so changing either rejects a stale frame binding.

The shared Bevy adapter maps vertical_size to FixedVertical viewport height. Aspect
ratio changes horizontal extent; camera distance does not change orthographic size.
Both modes use the same retained scene, GPU device, publication and color services.
Immutable frame depth retains projection, near and far. Perspective reverse-Z uses
near/z; orthographic uses far-z*(far-near). Zero remains background. This fixes the
otherwise incorrect use of the perspective decoder for orthographic frames.
