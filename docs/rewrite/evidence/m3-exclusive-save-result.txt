Exclusive committed-snapshot archive creation — 8 October 2026
Public save protocol and complete M3–M5 gates remain open.

Added feature-neutral fold_project::save_new(snapshot, path, check). It requires
CommittedSnapshot, serializes through the existing archive format into a same-
directory temporary file, flushes/syncs it, and publishes only when no destination
entry exists. Existing native save retains its explicit replacement behavior;
both paths share serialization and publication code.

Cancellation is checked before temporary creation, during serialization and just
before publication. SaveError::Cancelled means no archive was published; temporary
data is dropped. SaveError::AlreadyExists means an existing file/symlink entry was
preserved. After publication, success or DirectorySync is authoritative even if
cancellation arrives later. DirectorySync explicitly means the new archive is
visible but directory durability could not be confirmed. A future protocol worker
must preserve that committed outcome rather than replacing it with cancellation.

The existing tempfile no-clobber primitive uses no-replace rename on the reference
Linux platform, with atomic hard-link creation where that operation is unavailable.
Its latter path can leave the temporary link if unlink fails; this does not expose
a partial destination or overwrite an existing entry. No check-then-write race is
used for destination ownership.

Tests cover:
- Byte-preserving unsupported document payload and nested project/archive metadata.
- Existing archive and symlink preservation.
- Cancellation before work, during serialization and after staging/before publish;
  no destination or temporary file remains in the test directory.
- No cancellation recheck after successful publication hides the written archive.
- Two competing writers: exactly one complete archive wins, the other returns
  AlreadyExists, and load matches the winning committed snapshot exactly.
- Existing replacement-save failure/abandonment and all project regressions.
