Camera Plane Fill/Stroke partition fix — 8 October 2026
Resolves the single-path coplanar paint failure recorded in m4-camera-plane-paint-failure.txt.
Complete M3–M5 gates remain open.

The shared planar service now partitions Fill and Stroke tessellations into three
non-overlapping regions: Fill only, Stroke only, and their intersection. Camera
Plane preparation uses the original paints for exclusive regions and computes
Stroke-over-Fill in premultiplied linear color for the intersection, then converts
that result to the straight-color material contract. No material ordering, depth
bias, world-space displacement, bitmap replacement or alternate renderer is used.
Source paths and native text remain authoritative. Existing no-stroke/fill-only
meshes pass through without partitioning.

Partitioning uses convex half-plane clipping in f64, indexed triangle bounds and
piece bounds to reject unrelated work. Final local mesh coordinates remain f32.
Input triangle/index/planarity checks reject invalid geometry; each output and
intermediate piece list is bounded. Caller budget/cancellation checkpoints cover
conversion, index construction/query, clipping, emission and final mesh creation.
Scalar polygon work is charged in bounded batches of at most 32 vertices. The
existing request limit is unchanged; no unlimited fallback is introduced.

The first all-pairs prototype exceeded the native text conversion budget. A
triangle bounds index removed those comparisons. Per-vertex checkpoint charging
also exceeded that budget; bounded 32-vertex work units plus per-piece bounds
checks pass the same native fixture without raising its limit. This evidence is
not a large-scene performance or total renderer-memory qualification.

The diagnosing-bugs feedback loop is now green at the actual native renderer seam.
The proven cause was coplanar independent material ordering; disjoint geometry
removes that dependency for a single path's Fill/Stroke. Temporary diagnostic code
was not added to production. The regression keeps its exact analytic expectations.

Still unverified: GPU text and overlapping glyph/path paint order, arbitrary
transparent World intersections, held Camera Plane GPU frames, cross-camera
viewing, projected observations, public frame transport and physical artist/UI
acceptance. Do not generalize these rectangle results to complete Camera Plane
or full M3–M5 acceptance.
