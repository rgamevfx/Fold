At (40,30), opaque Fill/Stroke yields red [1,0,0,1] instead of green [0,1,0,1].

Passing combinations are observations from this run, not universal order guarantees.

Diagnosing-bugs skill applied; feedback loop reaches the actual native GPU path.
Local pinned Bevy 0.18.1 source inspection shows opaque phases bin by pipeline,
material bind group and mesh; transparent phases sort by view distance plus bias.
Native Camera Plane currently publishes fill and stroke as separate coplanar
StandardMaterials. Authored paint order is not represented at this boundary.

Ranked hypotheses for the next targeted probes:
1. Phase/bin ordering: changing alpha changes the draw phase, so opaque strokes
   render before fill in failing combinations. An explicit ordered paint path
   should fix overlap without changing geometric depth.
2. Depth precision: coincident samples could fail depth tests at different rounding;
   failures would track depth/camera changes rather than authored paint precedence.
3. Coverage: incorrect stroke tessellation would also affect the independent outer
   ring or half-alpha cases, unlike the current overlap-only pattern.

Do not treat material insertion order or a world-space Z offset as a qualified fix.
Bevy StandardMaterial.depth_bias also affects transparent distance sorting and
depth writes; using it needs evidence that other spatial occlusion stays correct.
The full goal still requires deterministic coplanar paint and transparency alongside
World geometry, actual text, retained frames, cross-camera viewing and public output.
