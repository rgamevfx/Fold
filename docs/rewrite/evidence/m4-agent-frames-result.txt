Exact-time public display frames — 8 October 2026
M3–M5 gates remain open.

New version-2 observe_frame command accepts a committed revision or candidate
generation, root Scene output UUID, exact output-relative time and dimensions.
Session supplies its shared GPU Host; no second device/queue is created. Discovery
reports availability only with an attached host and advertises encoding/limits.
CPU-only/no-host sessions reject frame requests explicitly.

One retained render worker admits at most two jobs and uses the shared Prepare
scheduler lane. Committed/candidate immutable snapshots carry project context;
jobs cannot mutate project or artist state. Existing job polling, cancellation,
lifetime, retained-result and byte limits apply. Renderer/decoder remain worker-local.
Owner teardown cancels jobs, closes result delivery and joins the GPU worker.

Rendering uses registered scene evaluation followed by the same project display
transform as preview. Replies contain opaque viewer-display RGBA8 hex pixels,
top-to-bottom rows, and provenance: epoch/document/base revision/candidate, exact
requested time, absolute scene and asset times, camera, font fingerprints, seed,
configuration/build/adapter and actual display-transform identity. Evaluation
CPU-image transfer counts are separate from the explicit display readback.

Positive dimensions are limited to 4096 per axis and 2,073,600 pixels. A full
1920x1080 reply fits the existing 16 MiB response bound. Encoding is lossless;
decode bytes once without an extra color transform. Fold skill includes public
CLI/MCP request and decoding examples. Public project save, clips/contact sheets,
crops, transparent linear delivery, exact duration endpoint and physical desktop
acceptance are still open.
