Public committed-project copy saving — 8 October 2026
M3 implementation evidence; complete M3–M5 gates remain open.

save_project_copy accepts a strict project guard (epoch, request_id, base; no
scope) and an absolute unused destination. It captures the committed snapshot on
the session owner and performs archive serialization/publication on an existing
bounded worker using fold_project::save_new. No second serializer or feature model
was added. Discovery and the generated shared CLI/MCP schema expose the command.
Project jobs have scope null; cancel_job supports strict project/document guards.

The saved result records path, revision, durable, warning and
session_file_changed=false. DirectorySync means publication occurred and retains
a saved result with durable=false. Worker completion records the published revision
so cancellation cannot relabel a visible archive as cancelled. Before publication,
cancellation leaves no destination. The cancellation unit test forces both orders
with barriers; late cancellation reports already_committed.

Actual CLI/socket and MCP/subprocess tests:
- Admit a save, then commit an artist edit before awaiting completion. Reopened
  archive equals the complete admitted snapshot; the live artist edit survives.
- Preserve session file routing and dirty state.
- Replay exact requests after revision advance and receive the original result.
- Reject existing destinations without replacement, changed arguments under the
  same UUID, stale bases and document-scoped cancellation of a project job.
- Native Open restores complete baseline state and resets the epoch; subsequent
  public inspection succeeds. Both transports produce identical archive bytes.
Native Open here uses application services, not physical desktop interaction.
